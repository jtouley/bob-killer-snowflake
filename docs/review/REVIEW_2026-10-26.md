## 3. Findings, ranked

### 3.1 Must fix (blocking)

1. **CI is red on `snowflake-host`.** `uv run mypy --strict --python-version 3.11 src/bob_killer_sis` parses
   numpy's `__init__.pyi` (pulled in by streamlit), which uses a PEP 695 `type` statement:
   `numpy/__init__.pyi:737: error: Type statement is only supported in Python 3.12 and greater`.
   Reproduced locally. This fix is verified to pass (`Success: no issues found in 2 source files`):
   ```toml
   [[tool.mypy.overrides]]
   # numpy's stubs use PEP 695 syntax; the 3.11 app check must not parse them.
   module = ["numpy", "numpy.*"]
   follow_imports = "skip"
   follow_imports_for_stubs = true
   ```
   It is a `pyproject.toml` change, so per the repo's rules it goes in as a `TDD-Phase: gate-change` commit that
   you review. I did not push it to `snowflake-host`.
2. **Nothing is merged or under review.** 113 commits sit on a branch with no PR. CODEOWNERS review of the
   gate-change commits (Phase 1, 9) has never happened, so the trust model in SPEC §1.2 is unverified in
   practice. Open a PR `snowflake-host → main` now, even as a draft, so CI and review run on it.
3. **The live job skips silently.** SPEC §6.4 says "Without a working connection the live suite **fails**; it
   never skips", and §1.6 item 7 says the job is required before merge. The workflow prints a `::notice::` and goes
   green. Either set the secrets (`tools/setup-ci-secrets.sh`) or make the job fail on PRs to `main` when secrets
   are missing.
4. **`BOB_KILLER_SVC` holds ACCOUNTADMIN** (SPEC §6.3, granted by CoCo on 2026-10-16). It is a key-pair service
   user whose private key sits on a laptop, and CoCo drives it. Run `REVOKE ROLE ACCOUNTADMIN FROM USER BOB_KILLER_SVC;` before any
   unattended run. This is likely also why `setup-ci-secrets.sh` was never run: it refuses admin users.

### 3.2 Should fix (speed)

5. **The process costs more than the product.** Two specs (848 + 717 lines), a 6-revision review record, a
   CoCo bridge with clone isolation, a state guard, a probe and a watchdog, and Cadence on top. All of it guards
   against an agent you could simply not use. The audit trail is good, but the bridge is now the critical path.
   For the MVP, let Claude Code build directly under the existing gates. The gates (`tdd_order`,
   `assertions_frozen`, `no_oracle_literals`, …) already catch a cheating commit from any author. Keep CoCo as
   an optional executor.
6. **The stages are built for SQLite paths.** `extract`/`graph`/`lift` bind a local `Path` through
   ContextVars. The fastest Snowflake path is to run them inside the procedure against a SQLite `workbook.db`
   in `/tmp`, then persist that file (and the IR YAML) to a stage. Mirroring every workbook table into Snowflake
   (`WB_CELLS` …) can wait until after the MVP. The bronze and `RUNS` tables already give Snowflake-queryable status.
7. **The demo scripts are the integration.** `docs/evidence/dbt_demo/gen_dbt.py` + `bk_udf.py` contain the
   working glue: workbook → IR → dbt, UDF registration and input seeding. Promote that logic into
   `hosts/snowflake/{udfs.py,dbt.py}` and the operator layer that now exists in `runtime/operators.py`, then
   delete the shim.
8. **The docs are stale or contradictory.** The `main` README has no status. The `snowflake-host` README status
   still lists operators/SUMIF/VLOOKUP as gaps, but commits `304ddf0` and `5064c67` added them. `labs/bob_killer/README.md`
   still says "Incubating in jtouley/sandbox".
9. **`jedi_wind` blocks the goal set.** Either pin a direct URL, or use the swap rule the user already approved
   (decision 1 in `SPEC-compiler-dbt.md`). For the MVP, define success on `mt_dot_budget` + `sgec_current`.
10. **Name review (L9) blocks generation.** Core decision 3 fails generation while any output-facing node is
    `needs_review`. A one-shot run cannot wait for a person. For the MVP, pre-approve the deterministic top
    choice per golden, recorded as a review row with you as reviewer, and keep the queue file for later.

### 3.3 Nice to have

11. `StarletteDeprecationWarning`: install `httpx2`, or pin it, so the warning doesn't turn into a break later.
12. openpyxl warnings on iWARM/SGEC (DrawingML, Data Validation extension) are expected. Assert them in a test
    so they don't hide new ones.
13. The `mutation` job only runs nightly on `main`. Since `main` has none of the runtime, it mutates nothing.

## 4. Comparable open-source projects (what to borrow)

No open-source project does the whole pipeline (Excel → graph → IR → dbt/Snowflake + app + exact-parity tests).
Excel-formula-to-SQL/dbt is an open niche. The closest is the QBX research prototype (VLDB 2005).

| Project | License | Borrow | Fit with Apache-2.0 |
| --- | --- | --- | --- |
| **IronCalc** (Rust, MIT/Apache, ~4.2k★, very active) | MIT/Apache | A **second, independent recalculation oracle**: lifts L1/L2 ("no Excel on this Mac", one input set per workbook). Seed for `crates/excel-kernel`. | Code reuse OK |
| **openpyxl** `formula.tokenizer` | MIT | Fuzz `graph/parser` against its tokens | OK |
| **XLParser** test corpus | MPL-2.0 | Thousands of real formulas for parser fuzzing (data only) | Data OK |
| **xlcalculator** | MIT (parts mixed) | Its `tests/xlfunctions_vs_excel` pattern: one Excel-saved workbook per function, used as an oracle fixture | Ideas, MIT parts |
| **pycel** `validate_calcs` | GPL-3 | Design of the cached-value parity check; OFFSET/INDIRECT handling | Ideas only |
| **formulas** (vinci1it2000) | EUPL | Function-family test layout, errors-as-values | Separate test-only dep at most |
| **HyperFormula** | GPL-3 | ~400-function list as a coverage checklist | Ideas only |
| **sqlglot** | MIT | Emit SQL for `sql_exact` nodes as ASTs, not Jinja strings; dialect-safe quoting; offline executor | OK |
| **oletools/olevba** (already a dep) | BSD | `extract_macros` + `analyze_macros` for the VBA inventory | OK |
| **python-calamine / fastexcel** | MIT | Fast cached-value reads for big bronze loads (JEDI) | OK |
| **ExceLint**, **Melford** (MSR) | research | Region/pattern anomalies to drive vectorized lift; hard-coded-number lint | Ideas only |
| Snowflake-Labs Streamlit demos / sfquickstarts | Apache | SiS upload/stage idioms | OK |

**Borrow now, in order:** (1) IronCalc as a second oracle in `verify/`, (2) the XLParser corpus to fuzz the
parser, (3) sqlglot for SQL-exact rendering, (4) the olevba analysis flags as VBA classification seeds,
(5) the xlcalculator-style per-function fixture layout.
